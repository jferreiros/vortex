Cómo se gestiona esta lista 4 reglas
1 · Se coge asignándose la issue
Cada tarea es una issue de GitHub con su código, T14. Te asignas antes de escribir la primera línea. Si no está asignada, está libre, aunque alguien la esté mirando. Esta página lee las issues en vivo: refresca y sale tu cara.
2 · Se cierra cuando pasa lo que dice "Terminado"
Cada tarea trae una condición comprobable, no una sensación. Se cierra con el commit o la PR que la cumple, y se pega la prueba en la issue: el caso de eval en verde, la llamada de práctica aceptada, la salida del comando.
3 · Una a la vez, y de tu carril
Una tarea asignada por persona. Coger tres es bloquear tres. El carril de color te dice la carpeta: trabajas dentro de ella y avisas en el canal antes de tocar contract.py.
4 · La lista se edita en el repo, no aquí
La fuente es docs/tasks.json. Cambias ahí, lanzas make tasks, y las issues y esta página se actualizan solas. Editar una issue a mano no rompe nada, pero se pierde en la siguiente sincronización.
