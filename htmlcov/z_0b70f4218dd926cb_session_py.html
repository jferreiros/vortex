1"""One ``CallSession`` per WebSocket. Nothing in here is shared between calls. 

2 

3The session owns: 

4- the ``ToolContext`` every tool receives (call_id, clock, clinic, log, submitter) 

5- the call's ``CallMemory``: the last rejection a tool returned and the last 

6 action a tool prepared but nobody sent 

7- the caller's agreement to that action (``confirm_prepared``), and the 

8 submission it fires so the model never has to ask a second time 

9- the submit client and the record of what was submitted 

10- the end-of-call bookkeeping: summary line, fallback submission, cleanup 

11 

12Lifecycle: ``CallSession.open(...)`` after the ``start`` message, ``close()`` 

13once the socket is gone. ``close()`` runs the 30-second-window logic. 

14"""

62# The tool the model calls to send an action itself. It goes through 

63# ``ctx.submitter``, so the session has to be told about it by name.

66# The tools that draw an action up without sending it. Once the caller has 

67# agreed, what they prepare goes out in the same turn: see

69PREPARE_TOOLS: tuple[str, ...] = ("prepare_booking", "prepare_reschedule", "prepare_cancel")

71# What counts as an action the platform holds for this call. A 200 or a 409 

72# (the same action twice) is a record; everything else is not, ``dry_run`` 

73# included - see ``CallSession.has_accepted_submission``. 

74ACCEPTED_STATUSES: tuple[str, ...] = ("accepted", "duplicate")

76# The tools that answer with the rule the clinic applied, named in the closed 

77# vocabulary the platform scores. Their reason is the call's verdict: a refusal 

78# has to carry it verbatim, whatever the model remembered. See 

79# ``CallMemory.last_verdict`` and the override in ``vortex/line/submit.py``. 

80VERDICT_TOOLS: frozenset[str] = frozenset({"check_eligibility", "find_slots"})

82# The plan a booking is billed to when neither the patient's record nor the slot 

83# names one. The platform validates ``policy_id`` against ``INSURERS``, so a 

84# draft has to pick something the schema knows; self-pay is the one that claims 

85# no cover we have not seen. 

86SELF_PAY_POLICY = "privado" 

87 

88# The refusal that wins nothing. ``out_of_scope`` claims the clinic line does not 

89# handle the request at all, and of the published cases not one is accepted on 

90# it: every ending is BOOK, REGISTER, or a refusal that names its rule. Where the

134@dataclass 

135class CallMemory: 

136 """What the call learned, kept for the moment the line goes dead. 

137 

138 Two things decide a silent call's last action: the last rule that bit (so 

139 the refusal can name it instead of ``out_of_scope``, which only ever matches 

140 problem 14) and the last action a tool prepared that nobody sent. 

141 

142 One instance per ``ToolContext``, attached by ``CallSession.open`` and 

143 reachable with ``CallMemory.of(ctx)``. The conversation lane calls 

144 ``ctx.memory.mark_confirmed()`` the moment the caller says yes to what we 

145 read back; that is the only hook the prompt lane needs. 

146 

147 The two memories exclude each other on purpose: a refusal after a prepared 

148 action drops the action (the rule bit after we drew it up), and a prepared 

149 action - or free slots coming back - drops the rejection (whatever blocked 

150 us no longer stands). 

151 """ 

152 

153 last_rejection: Rejection | None = None 

154 last_rejection_tool: str = "" 

155 # The subset of ``last_rejection`` that came from a rule, not from prose: 

156 # an eligibility verdict or a provider ``find_slots`` reported as blocked. 

157 # It is the reason a refusal must carry, so ``submit_action`` forces it. 

158 last_verdict: Rejection | None = None 

159 last_verdict_tool: str = "" 

160 # The same reason, kept across the action a tool later prepares around it. 

161 # A plan nobody confirmed must not cost the call a named reason: replacing 

162 # one with ``out_of_scope`` only ever loses the case. Free slots clear it, 

163 # because by then the rule no longer stands. 

164 stored_reason: Rejection | None = None 

165 stored_reason_tool: str = "" 

166 # A lookup ran and nobody was identified. The call ends on 

167 # ``patient_not_found``, which says what happened; ``out_of_scope`` claims 

168 # we could not serve the request at all, which is a different call. 

169 identity_pending: bool = False 

170 # The two halves of a booking the call had in hand: who is calling, and a 

171 # slot the platform offered. Kept apart from ``prepared`` because a call can 

172 # learn both and die before any tool draws the action up. 

173 identified_patient: PatientRecord | None = None 

174 # Who the dialling line belongs to, from the caller-id lookup at open. Kept 

175 # apart from ``identified_patient`` because it identifies the *line*: on a 

176 # third-party call the phone's owner is not the patient. A lookup the 

177 # conversation makes always wins; this is only what the call started with. 

178 caller_line: CallerLineMatch | None = None 

179 free_slot: Slot | None = None 

180 prepared: Action | None = None 

181 prepared_tool: str = "" 

182 # Set by the conversation lane when the caller agrees to ``prepared``. It 

183 # survives a re-prepare of the same plan: the caller often says yes before 

184 # the model draws the action up again. 

185 confirmed: bool = False

246 def draft_booking(self) -> BookAction | None: 

247 """The booking the call had every part of and nobody drew up. 

248 

249 ``None`` unless the directory identified somebody and the platform 

250 offered a slot: a booking is only ours to draft off ids the API gave us. 

251 The slot is the most recent search's first, which is the one the caller 

252 was being read back when the line died. 

253 

254 Who it is booked for is whoever the conversation identified; failing 

255 that, the owner of the dialling line, which the directory resolved from 

256 the caller id before the call began. The line owner is a weaker claim - 

257 a third-party call books someone else - but a slot was found for this 

258 call, so the alternative here is a refusal that scores nothing. 

259 """ 

260 patient, slot = self.patient_on_record, self.free_slot 

261 if patient is None or slot is None or self.identity_pending: 

262 return None 

263 return booking_for(patient, slot)

265 def observe(self, tool: str, result: Any) -> None: 

266 """Remember whatever a tool result says about where the call stands. 

267 

268 Reads the contract's own field names, so no lane tool has to know this 

269 exists: ``rejection`` on every result that can refuse, ``action`` on the 

270 ``prepare_*`` and ``build_registration`` results, ``slots``/``blocked`` 

271 on availability, ``status`` on the identity lookup. 

272 """ 

273 if isinstance(result, FindPatientResult): 

274 self.identity_pending = result.status != "found" 

275 if result.patient is not None and result.status == "found": 

276 self.identified_patient = result.patient 

277 

278 rejection = getattr(result, "rejection", None) 

279 if isinstance(rejection, Rejection): 

280 self.remember_rejection(tool, rejection) 

281 action = getattr(result, "action", None) 

282 if action is not None: 

283 self.remember_prepared(tool, action) 

284 

285 slots = getattr(result, "slots", None) 

286 if slots is None: 

287 return 

288 # find_slots answers a blocked provider with the rule that blocked it 

289 # and no rejection - naming it as a refusal is the rules lane's call. 

290 # At the end of a dead call it is the only reason we have. 

291 blocked = getattr(result, "blocked", None) or [] 

292 if slots: 

293 self.free_slot = slots[0] 

294 self.forget_rejection() 

295 self.forget_stored_reason() 

296 elif blocked and rejection is None: 

297 first = blocked[0] 

298 self.remember_rejection( 

299 tool, Rejection(reason=first.reason, detail=getattr(first, "detail", ""))

375 async def resolve_caller_line(self) -> CallerLineMatch: 

376 """Look the dialling line up before the caller speaks, and remember it. 

377 

378 Called once by the voice pipeline while it is still being built, so the 

379 system prompt can name the caller instead of spending the first minute 

380 of a three-minute call asking who they are. Bounded by 

381 ``caller_id_lookup_timeout_secs``: the note is never worth holding the 

382 greeting for, and without it the call simply asks as it always did. 

383 """ 

384 try: 

385 match = await asyncio.wait_for( 

386 resolve_caller_line(self.ctx), 

387 timeout=self.settings.caller_id_lookup_timeout_secs, 

388 ) 

389 except TimeoutError: 

390 self.ctx.log.event("identity.caller_line_timed_out") 

391 match = CallerLineMatch() 

392 self.memory.caller_line = match 

393 return match

395 async def call_tool(self, name: str, raw_args: dict[str, Any]) -> BaseModel: 

396 """Run one tool through the registry and keep what the end of the call needs. 

397 

398 The registry validates, runs and logs; the session remembers. Two things 

399 are recorded here and nowhere else: 

400 

401 - what the result says about where the call stands (``CallMemory``); 

402 - the model's own ``submit_action`` calls. Those reach the platform 

403 through ``ctx.submitter`` without passing ``CallSession.submit``, so 

404 without this the session would end a booked call believing it had 

405 submitted nothing and send a refusal on top of the booking. 

406 

407 An accepted submission also arms the hangup: the call has nothing left 

408 to do, so the pipeline ends it after the farewell. 

409 """ 

410 result = await registry.call_tool(name, self.ctx, raw_args) 

411 if name == SUBMIT_TOOL and isinstance(result, SubmitResult): 

412 self.submitted.append(result) 

413 try: 

414 sent = SubmitInput.model_validate(raw_args).action 

415 except ValidationError: # pragma: no cover - the registry validated it already 

416 pass 

417 else: 

418 # What left the process, reason override included, so the 

419 # fallback can tell a re-send from a first try. 

420 self.sent_actions.append(with_verdict_reason(self.ctx, sent)) 

421 if result.status in ACCEPTED_STATUSES: 

422 self.arm_hangup("submit_accepted") 

423 else: 

424 self.memory.observe(name, result) 

425 await self._submit_after_prepare(name) 

426 return result

428 def confirm_prepared(self, why: str) -> None: 

429 """The caller said yes to the plan we read back. Never ask a second time. 

430 

431 Called by the conversation lane's ``ConfirmationPolicy`` the moment an 

432 affirmation lands on a read-back. It records the agreement for the 

433 end-of-call fallback and, when an action is already drawn up, sends it: 

434 asking the same question twice is what cost the scored run its wall 

435 clock, and nothing un-sends an action that is already submitted. 

436 

437 Synchronous on purpose. It is called from the frame path, where awaiting 

438 an HTTP POST would hold the caller's own audio, so the submission goes 

439 out as a task and ``close`` waits for it. 

440 """ 

441 memory = self.memory 

442 if memory.confirmed: 

443 return 

444 memory.mark_confirmed() 

445 self.ctx.log.event( 

446 "confirm.affirmed", 

447 why=why, 

448 prepared_by=memory.prepared_tool, 

449 has_prepared=memory.prepared is not None, 

450 ) 

451 if memory.prepared is not None: 

452 self._spawn(self.submit_confirmed_prepared("affirmation"))

454 async def submit_confirmed_prepared(self, trigger: str) -> SubmitResult | None: 

455 """Send the prepared action the caller has agreed to, once. 

456 

457 ``None`` when there is nothing to send: no action drawn up, no agreement 

458 yet, or this exact action already left. 

459 

460 This does not arm the hangup. The call may still have a second thing to 

461 do (a cancel and a booking are two actions), and the caller has not been 

462 said goodbye to yet; the model's own ``submit_action`` - a duplicate of 

463 this one, which the platform answers 409 - is what ends the call, as it 

464 did before. 

465 """ 

466 memory = self.memory 

467 action = memory.prepared 

468 if action is None or not memory.confirmed or action in self.sent_actions: 

469 return None 

470 self.ctx.log.event( 

471 "submit.on_confirmation", 

472 trigger=trigger, 

473 route=action_route(action), 

474 prepared_by=memory.prepared_tool, 

475 ) 

476 return await self.submit(action)

478 async def _submit_after_prepare(self, tool: str) -> None: 

479 """A ``prepare_*`` after the caller's yes needs no second question.""" 

480 if tool in PREPARE_TOOLS:

483 def _spawn(self, coro: Any) -> None: 

484 """Run a submission off the frame path, and keep hold of it.""" 

485 try: 

486 task = asyncio.get_running_loop().create_task(coro) 

487 except RuntimeError: # no loop: nothing can be sent from here 

488 coro.close() 

489 return 

490 self._pending.add(task) 

491 task.add_done_callback(self._pending_done) 

492 

493 def _pending_done(self, task: asyncio.Task[Any]) -> None: 

494 self._pending.discard(task) 

495 if not task.cancelled() and task.exception() is not None: 

496 self.ctx.log.event("submit.on_confirmation_failed", error=repr(task.exception()))

498 def arm_hangup(self, reason: str) -> None: 

499 """The call is done: let the pipeline end it once the agent stops talking. 

500 

501 Only an action the platform *holds* arms this. A rejection, a late 

502 submission or a dry run leaves the call running, because the model may 

503 still fix what it sent and the end-of-call fallback is still the last 

504 word. Armed once, it stays armed: the first reason is the true one. 

505 """ 

506 if not self.hangup_reason: 

507 self.hangup_reason = reason

511 """Has the call earned the right to hang up from our side?"""

514 async def submit(self, action: Action) -> SubmitResult: 

515 result = await submit_action(self.ctx, SubmitInput(action=action)) 

516 self.submitted.append(result) 

517 self.sent_actions.append(with_verdict_reason(self.ctx, action)) 

518 return result

520 @property 

521 def has_accepted_submission(self) -> bool: 

522 """Does the platform hold an action for this call? 

523 

524 ``dry_run`` is not acceptance: with no ``PLATFORM_API_KEY`` nothing 

525 leaves the process, so a dry run is a line in the log, not a record on 

526 the platform. Leaving it out is what keeps the fallback exercised - and 

527 logged - in fake mode, which is the only mode the tests and the offline 

528 rehearsals run in. ``late``, ``rejected``, ``unknown_call`` and 

529 ``error`` are not acceptance either: the platform has nothing, so the 

530 fallback still gets its try inside the window. 

531 """ 

532 return any(r.status in ACCEPTED_STATUSES for r in self.submitted)

534 async def close(self, reason: str = "socket_closed", **extra: Any) -> None: 

535 """End-of-call bookkeeping. Safe to call twice.""" 

536 if self._closed: 

537 return 

538 self._closed = True 

539 self.end_reason = reason 

540 self.ctx.log.event( 

541 "call.ended", 

542 reason=reason, 

543 media_frames_in=self.media_frames_in, 

544 media_frames_out=self.media_frames_out, 

545 **extra, 

546 ) 

547 try: 

548 await asyncio.wait_for( 

549 self._fallback_if_silent(), 

550 timeout=self.settings.submit_window_secs 

551 - self.settings.submit_deadline_margin_secs, 

552 ) 

553 except TimeoutError: 

554 self.ctx.log.event("submit.fallback_timed_out") 

555 finally: 

556 self.ctx.log.summary(reason=reason) 

557 await self.submitter.aclose()

559 async def _fallback_if_silent(self) -> None: 

560 """Submitting nothing always fails. A typed refusal never scores worse. 

561 

562 Scoring is binary per case, so a wrong action costs exactly what silence 

563 costs and a right one wins the case. The branches below are ordered by 

564 how likely each is to be the answer the case expects. 

565 

566 A submission fired by ``confirm_prepared`` may still be in flight when 

567 the socket dies, so it is waited for first: otherwise this would send a 

568 refusal on top of the booking the caller agreed to. 

569 """ 

570 if self._pending: 

571 await asyncio.gather(*tuple(self._pending), return_exceptions=True) 

572 if self.has_accepted_submission: 

573 return 

574 branch, action, why = self.fallback_action() 

575 if action == UNSCORED_REFUSAL: 

576 booking = await self.cold_booking() 

577 if booking is not None: 

578 branch = "cold_booking" 

579 why = f"{why}, and out_of_scope wins no case: booked what the line points at" 

580 action = booking 

581 with observe_span( 

582 "submit-fallback", 

583 input={"branch": branch, "why": why, "route": action_route(action)}, 

584 ) as span: 

585 await self._send_fallback(branch, action, why, span) 

586 

587 async def _send_fallback(self, branch: str, action: Action, why: str, span: Any = None) -> None: 

588 # An earlier send of this action may have returned error / dry_run / 

589 # rejected: the platform holds nothing. Retry so an ambiguous first 

590 # request can still land as accepted or duplicate (409). 

591 retrying = action in self.sent_actions 

592 self.ctx.log.event( 

593 "submit.fallback", 

594 branch=branch, 

595 why=why, 

596 route=action_route(action), 

597 skipped=False, 

598 retrying=retrying, 

599 sent_so_far=len(self.submitted), 

600 ) 

601 if span is not None: 

602 span.update(output={"skipped": False, "retrying": retrying, "branch": branch}) 

603 await self.submit(action)

605 async def cold_booking(self) -> BookAction | None: 

606 """The booking the dialling line implies, for a call that resolved nothing. 

607 

608 Reached only where the fallback has named nothing and would send 

609 ``out_of_scope``, which no published case accepts and which is therefore 

610 a certain zero. The call still knows who dialled: the caller-id lookup 

611 runs before the greeting, so a call the agent never got a word into ends 

612 holding a ``patient_id`` from ``/directory`` and the habits mined off 

613 that patient's visit history. This asks the platform for the slot those 

614 habits point at and books it. 

615 

616 ``None`` whenever the guess would not be ours to make: nobody on the 

617 line, no slot free, or the platform did not answer in time. Every one of 

618 those leaves the refusal the fallback already chose in place - a booking 

619 nobody sends is worth less than a refusal that goes out inside the 

620 window. 

621 """ 

622 patient = self.memory.patient_on_record 

623 if patient is None: 

624 return None 

625 try: 

626 slot = await asyncio.wait_for( 

627 self._first_slot_for(patient), 

628 timeout=self.settings.cold_booking_timeout_secs, 

629 ) 

630 except TimeoutError: 

631 self.ctx.log.event("submit.cold_booking_timed_out", patient_id=patient.patient_id) 

632 return None 

633 except Exception as exc: 

634 self.ctx.log.event("submit.cold_booking_failed", detail=f"{type(exc).__name__}: {exc}") 

635 return None 

636 if slot is None: 

637 return None 

638 booking = booking_for(patient, slot) 

639 self.ctx.log.event( 

640 "submit.cold_booking", 

641 patient_id=booking.patient_id, 

642 provider_id=booking.provider_id, 

643 location_id=booking.location_id, 

644 appointment_type_id=booking.appointment_type_id, 

645 slot=booking.slot, 

646 from_line=self.memory.identified_patient is None, 

647 ) 

648 return booking

650 async def _first_slot_for(self, patient: PatientRecord) -> Slot | None: 

651 """The first slot the platform offers this patient, their habits first. 

652 

653 Two searches at most: the doctor and site every past visit of theirs 

654 used, then general practice anywhere. ``/availability`` answers no query 

655 that names neither a provider nor a specialty, so the open search still 

656 has to name one, and general practice is what a scheduling line is asked 

657 for when it was not asked for anything. 

658 

659 Both go through the diary lane's ``find_slots``, so the same-day rule, 

660 the site calendar and the span the platform accepts stay in one place, 

661 and the slots come back priced against this patient's own plan. 

662 """ 

663 today = self.ctx.now.astimezone(MADRID).date() 

664 window = { 

665 "patient_id": patient.patient_id, 

666 "date_from": today, 

667 "date_to": today + timedelta(days=COLD_BOOKING_HORIZON_DAYS), 

668 } 

669 queries = [] 

670 provider, location = self._habits_of(patient) 

671 if provider: 

672 queries.append(FindSlotsInput(provider_id=provider, location_id=location, **window)) 

673 queries.append(FindSlotsInput(specialty_id=DEFAULT_SPECIALTY, **window)) 

674 for query in queries: 

675 result = await find_slots(self.ctx, query) 

676 if result.slots: 

677 return result.slots[0] 

678 return None

680 def _habits_of(self, patient: PatientRecord) -> tuple[str | None, str | None]: 

681 """The doctor and site this patient has always used, or ``(None, None)``. 

682 

683 Read from what the identity lane mined in the background when the caller 

684 id resolved, and only when it mined it for this patient: a call that 

685 identified somebody else later must not book against the line owner's 

686 habits. Unanimous or nothing - a patient who has seen two doctors has no 

687 habit worth guessing from. 

688 """ 

689 habits = self.ctx.state.get(PATIENT_PREFERENCES_KEY) or {} 

690 if habits.get("patient_id") != patient.patient_id: 

691 return None, None 

692 return habits.get("provider_preference") or None, habits.get("location_preference") or None

694 def fallback_action(self) -> tuple[str, Action, str]: 

695 """The action a silent call ends on: (branch, action, why).""" 

696 memory = self.memory 

697 

698 # (a) Something was drawn up, agreed to, and never sent. The caller's 

699 # yes outranks every reason below it, a named rule included. 

700 if memory.prepared is not None and memory.confirmed: 

701 return ( 

702 "prepared", 

703 memory.prepared, 

704 f"{memory.prepared_tool} prepared an action nobody sent " 

705 f"(confirmed={memory.confirmed})", 

706 ) 

707 

708 # (b) The last rule that bit. This is the branch that earns points: 

709 # out_of_scope matches problem 14 and nothing else, while a named 

710 # reason matches the refusal endings of problems 6, 7, 10 and 16. 

711 # A red flag is the one ending the platform expects on /escalate. 

712 # The verb is the rejection's, the reason the rules' verdict where 

713 # the call holds one: the same swap ``submit_action`` makes, done 

714 # here so the branch we log is the action that goes out and the 

715 # re-send check in ``_send_fallback`` compares like with like. 

716 if memory.last_rejection is not None: 

717 reason = memory.last_rejection.reason 

718 return ( 

719 "last_rejection", 

720 with_verdict_reason(self.ctx, refusal_for(reason)), 

721 f"{memory.last_rejection_tool} refused: {reason}", 

722 ) 

723 

724 # (c) A rule bit earlier and a tool then drew up a plan around it that 

725 # nobody confirmed. The rule is still the last thing we learned, so 

726 # it names the ending: a stored reason is never worth trading for 

727 # out_of_scope. 

728 if memory.stored_reason is not None: 

729 reason = memory.stored_reason.reason 

730 return ( 

731 "stored_reason", 

732 refusal_for(reason), 

733 f"{memory.stored_reason_tool} refused: {reason}, before a plan nobody confirmed", 

734 ) 

735 

736 # (d) A plan the caller never got to agree to, with no rule against it. 

737 # Scoring is binary per case, so an action the case does not accept 

738 # costs exactly what a refusal it does not accept costs - and of the 

739 # 23 published cases every single one ends on BOOK, REGISTER or one 

740 # of three named refusals, never on the out_of_scope this used to 

741 # fall through to. A call that got as far as drawing an action up is 

742 # a call whose ending we already know. 

743 if memory.prepared is not None: 

744 return ( 

745 "prepared_unconfirmed", 

746 memory.prepared, 

747 f"{memory.prepared_tool} prepared an action nobody confirmed", 

748 ) 

749 

750 # (e) No plan, but the call holds both halves of one: the patient the 

751 # directory identified and a slot the platform offered. Both ids 

752 # come from the API, so the draft is exact where it is right. 

753 draft = memory.draft_booking() 

754 if draft is not None: 

755 return ( 

756 "draft_booking", 

757 draft, 

758 "the call identified a patient and held a free slot, and drew nothing up", 

759 ) 

760 

761 # (f) Nobody said anything we could act on: a dropped or silent call. 

762 if self.ctx.log.user_turns == 0: 

763 return ( 

764 "no_turns", 

765 NoAction(reason="out_of_scope"), 

766 "the caller never said anything we could act on", 

767 ) 

768 

769 # (g) The line died with the lookup still open: a patient was searched 

770 # for and none was identified. That is patient_not_found, and it is 

771 # the one thing out_of_scope certainly is not - the request was ours 

772 # to serve, we just never learned whose it was. 

773 if memory.identity_pending: 

774 return ( 

775 "identity_pending", 

776 NoAction(reason="patient_not_found"), 

777 "a lookup ran and identified nobody", 

778 ) 

779 

780 # (h) A real conversation that resolved nothing, and no rule to name. 

781 # NO_ACTION, not ESCALATE. The problem set pairs ESCALATE with one 

782 # ending only - a red flag, with medical_emergency - and branch (b) 

783 # already covers it from triage's own rejection. An ESCALATE 

784 # anywhere else is a verb no case accepts, so it can only lose a 

785 # case that NO_ACTION might still win: out_of_scope is the expected 

786 # ending of the adversarial cases and the right shape of answer 

787 # wherever we simply could not tell what was being asked. 

788 return ( 

789 "default", 

790 NoAction(reason="out_of_scope"), 

791 "the call ended with nothing resolved and no rule to name", 

792 )
